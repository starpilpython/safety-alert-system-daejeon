# 투윤백: 대전 발화 데이터 분석 및 KCBERT-LLM 결합 모델 프로젝트

## 1. 프로젝트 소개

본 프로젝트는 '대전광역시 중구' 관련 민원 또는 대화로 추정되는 발화 데이터를 심층적으로 분석하고, 이를 바탕으로 고성능 자연어 처리 모델을 구축하는 것을 목표로 합니다.

주요 수행 과제는 다음과 같습니다.
- **데이터 분석**: 발화 데이터의 특성을 파악하고, `BERTopic`을 활용하여 주요 주제와 키워드를 도출합니다.
- **모델 파인튜닝**: 한국어 데이터에 특화된 `KCBERT` 모델을 프로젝트 데이터셋에 맞게 미세조정(Fine-tuning)하여 도메인 특화 성능을 향상시킵니다.
- **LLM 결합**: 파인튜닝된 KCBERT와 경량 LLM인 `Gemma` 모델을 결합하여, 문맥 이해 능력과 생성 능력을 모두 갖춘 하이브리드 모델을 구현합니다.
- **API 구현**: `FastAPI`를 사용하여 개발된 모델을 외부에서 사용할 수 있도록 API를 제공하는 부분까지 고려되었습니다.

최종 결과물인 '투윤백'은 이러한 과정을 거쳐 개발된 서비스 또는 데모의 명칭으로 보입니다.

### 4.3. 노트북 상세 설명 (데이터 분석 및 모델링 과정)
프로젝트의 핵심 분석 및 모델링 과정은 아래 4개의 Jupyter Notebook에 단계별로 구현되어 있습니다. 각 노트북을 순서대로 실행하며 데이터 처리부터 최종 모델 적용까지의 전 과정을 확인할 수 있습니다.

1.  **`01_data_analysis.ipynb`: 데이터 탐색 및 심층 분석**
    -   **목표**: 원본 발화 데이터의 특성을 파악하고 숨겨진 인사이트를 도출합니다.
    -   **주요 분석 내용**:
        -   **기본 탐색**: 데이터의 크기, 결측치, 주요 변수(`doll_id`, `text`, `uttered_at`)를 확인합니다.
        -   **시간대별 분석**: 하루 24시간 동안의 발화 패턴을 분석하여, 어르신들의 활동이 집중되는 시간대(오전 9-10시, 오후 5-8시)를 시각화(라인 차트, 히트맵)합니다. 이를 통해 생활 리듬과 심야 시간대 이상 신호 탐지 가능성을 확인합니다.
        -   **사용자별 분석**: 사용자(`doll_id`)별 발화량 분포를 분석하여, 소수의 핵심 사용자 그룹이 전체 대화의 상당 부분을 차지하는 파레토 법칙(Pareto)을 확인합니다.
        -   **단어 빈도 분석**: `soynlp`와 `kiwipiepy`를 활용해 텍스트를 토큰화하고, 워드클라우드 및 막대그래프로 주요 키워드를 시각화합니다. '건강', '관계', '감정'이라는 세 가지 핵심 주제 영역을 식별합니다.
        -   **토픽 모델링**: `BERTopic`을 사용하여 문맥적 의미를 기반으로 발화 내용을 100개 이상의 세부 토픽으로 군집화하고, 이를 다시 5개의 핵심 카테고리(건강, 가족, 일상, 감정, 기능)로 재구성하여 대화의 주요 주제를 입체적으로 분석합니다.

2.  **`02_data_labeling(gpt 활용).ipynb`: LLM을 활용한 데이터 라벨링**
    -   **목표**: 단답형 발화가 많아 키워드 분석만으로는 한계가 있는 데이터를 보완하기 위해, LLM을 활용하여 각 발화의 위험도를 자동으로 분류하고 라벨을 생성합니다.
    -   **핵심 기술**:
        -   **모델**: 로컬 CPU에서도 구동 가능한 경량 LLM인 `Gemma-3-1B-IT` GGUF 모델을 사용합니다.
        -   **프롬프트 엔지니어링**: 발화 내용을 4가지 위험 등급(`positive`, `danger`, `critical`, `emergency`)으로 분류하도록 상세한 지침이 포함된 시스템 프롬프트를 설계합니다.
        -   **대화 턴 병합**: 10분 이내의 연속된 발화를 하나의 문맥으로 묶어, 단일 발화보다 더 정확한 분석이 가능하도록 데이터를 가공합니다.
    -   **결과**: 분석된 모든 발화에 대해 위험도 라벨을 부여하고, 이를 `(데이터라벨링)전체발화데이터(대전중구).xlsx` 파일로 저장하여 다음 단계의 모델 학습을 위한 데이터셋을 구축합니다.

3.  **`03_fine_tuning(kcbert_모델).ipynb`: KCBERT 모델 파인튜닝**
    -   **목표**: 이전 단계에서 라벨링된 데이터를 사용하여, 한국어 특화 모델인 `KCBERT`를 4단계 위험도 분류 작업에 맞게 미세조정(Fine-tuning)합니다.
    -   **주요 과정**:
        -   **데이터 분할**: 라벨 비율을 동일하게 유지하는 계층적 분할(Stratified Split)을 통해 데이터를 훈련(60%), 검증(20%), 테스트(20%) 세트로 나눕니다.
        -   **클래스 불균형 처리**: 데이터 불균형 문제(대부분 `positive`)를 해결하기 위해, 손실 함수(`CrossEntropyLoss`)에 클래스 가중치(Class Weight)를 적용하여 소수 클래스(`critical`, `emergency`)의 중요도를 높입니다.
        -   **학습 및 평가**: 5 에포크(Epoch) 동안 모델을 학습시키며, 매 에포크마다 검증 세트의 F1-Score를 측정합니다. 가장 성능이 좋은 시점의 모델을 `best_kcbert_model.pt`로 저장합니다.
        -   **최종 성능 검증**: 학습에 전혀 사용되지 않은 테스트 세트를 통해 모델의 최종 성능을 객관적으로 평가하고, 상세 리포트와 혼동 행렬(Confusion Matrix)을 생성하여 과적합 여부를 점검합니다.

4.  **`04_bert_llm 결합 모델.ipynb`: KCBERT-LLM 하이브리드 모델 구현 및 적용**
    -   **목표**: 파인튜닝된 KCBERT와 LLM(Gemma)을 결합하여, '분류'와 '설명' 기능을 모두 갖춘 실용적인 AI 에이전트를 구현합니다.
    -   **아키텍처 (하이브리드 접근)**:
        -   **1단계 (분류)**: 사용자의 발화가 입력되면, 먼저 빠르고 효율적인 `KCBERT` 모델이 위험 등급을 예측합니다.
        -   **2단계 (설명)**: `KCBERT`가 내린 결론을 `Gemma` LLM에 전달합니다. 이때 LLM은 새로운 판단을 하는 것이 아니라, "이 문장이 왜 'critical' 등급으로 분류되었는지 설명해줘" 와 같이 주어진 결론에 대한 논리적 근거를 생성하는 '설명자' 역할을 수행합니다.
    -   **구현**: `LangGraph`를 사용하여 '파일 분석 → 대화 턴 병합 → 위험도 분류(KCBERT) → 근거 생성(LLM)'으로 이어지는 전체 파이프라인을 구축합니다.
    -   **최종 산출물**: 각 발화별 위험 등급과 함께 LLM이 생성한 상세 분석 보고서를 포함하는 최종 결과 테이블을 생성하고, 이를 `(분석결과)발화데이터(대전중구).xlsx` 파일로 저장합니다. 이는 데모 애플리케이션의 핵심 로직으로 활용됩니다.

## `demo` 디렉터리 (AI 기반 데스크톱 애플리케이션) 상세 설명

**Version:** 0.1.0

### 1. 개요

본 프로젝트는 대전시의 발화(發話) 데이터를 기반으로, BERT와 LLM(Large Language Model)을 결합하여 실시간으로 위험 등급을 분석하고, 특정 위험 등급에 도달했을 때 자동으로 관계자에게 알림을 전송하는 AI 기반 데스크톱 알림 서비스입니다. 특히, 분석 후 사용자의 버튼 액션을 통해 n8n 워크플로우를 트리거하여 카카오톡과 같은 다양한 채널로 알림을 보낼 수 있도록 설계되었습니다. Tauri 프레임워크를 사용하여 웹 기술(HTML, CSS, JavaScript)을 프론트엔드로, Rust를 애플리케이션 코어로 활용하며, 별도로 구성된 Python AI 서버와 연동하여 고도화된 자연어 처리 및 추론 기능을 제공합니다.

특히, 야간 등 즉각적인 대처가 어려운 상황에서 위험 상황 발생 시 1차적으로 담당 공무원, 2차적으로 보호자 등에게 자동으로 알림을 발송하며, 위급 상황 시에는 119나 112와 같은 긴급 구조 기관에 자동으로 알릴 수 있도록 설계되어 인명 및 재산 피해를 최소화하는 것을 목적으로 합니다. 사용자 인터페이스는 Tauri의 웹뷰(WebView)를 통해 렌더링되며, 실제 AI 모델 연산은 로컬 Python 서버에서 수행된 후 그 결과가 애플리케이션에 표시되는 하이브리드 아키텍처를 채택하고 있습니다.

### 2. 기술 아키텍처 및 파일 구조

본 애플리케이션은 웹 기술을 사용한 프론트엔드, Rust 기반의 코어 로직, Python으로 실행되는 AI 백엔드가 결합된 하이브리드 구조입니다.

```

┌──────────────────┐     ┌──────────────────────┐     ┌────────────────────────┐

│   Frontend       │     │  Tauri Core (Rust)   │     │  Python AI Backend     │

│ (HTML, CSS, JS)  │◀───▶│ (Window, Commands)   │◀───▶│   (FastAPI)            │

└──────────────────┘     └──────────────────────┘     └────────────────────────┘

       ▲                         ▲                         │        ▲

       │ (Webview)               │ (System Calls)          │ (HTTP/RPC)

       ▼                         ▼                         ▼        │

┌──────────────────┐     ┌──────────────────────┐     ┌────────────────────────┐

│   User Interface │     │   Native OS Features │     │   AI Models (LLM)      │

│ (Button Trigger) │     │     (n8n Flow)       │     │   External Services    │

└──────────────────┘     └──────────────────────┘     └────────────────────────┘

```

#### 2.1. Frontend (`demo/src/`)
-   **역할**: 사용자 인터페이스(UI) 및 사용자 경험(UX)을 담당합니다.
-   **기술**: `HTML`, `CSS`, `JavaScript`
-   **주요 파일**:
    -   `index.html`: 애플리케이션 UI의 기본 골격을 정의하는 HTML 파일.
    -   `main.js`: UI 이벤트 처리, 상태 관리 및 Rust 백엔드로의 API 요청 등 프론트엔드 로직의 시작점.

#### 2.2. Tauri Core (Rust Backend) (`demo/src-tauri/`)
-   **역할**: 애플리케이션의 메인 로직, 시스템 접근 및 Python AI 서버와의 통신을 담당합니다. 또한, AI 분석 결과에 따라 사용자 인터페이스의 버튼 액션을 통해 `n8n` 워크플로우를 트리거하여 카카오톡 등 외부 알림 서비스로 메시지를 전송하는 역할을 합니다.
-   **기술**: `Rust`
-   **주요 파일**:
    -   `tauri.conf.json`: 앱의 이름, 버전, 아이콘, 권한, 네이티브 API 허용 목록 등 Tauri 애플리케이션의 핵심 설정을 관리하는 파일.
    -   `src/main.rs`: Rust 코드의 진입점. 윈도우 생성, 플러그인 초기화 및 `#[tauri::command]`로 정의된 함수를 등록하여 프론트엔드와 통신하는 역할을 합니다.
    -   `Cargo.toml`: Rust 프로젝트의 의존성(라이브러리)을 관리하는 파일.

#### 2.3. Python AI Backend (`demo/backend/`)
-   **역할**: 실제 AI 모델을 로드하고, 추론(Inference) 요청을 처리하는 API 서버입니다.
-   **기술**: `Python`, `FastAPI`, `PyTorch`
-   **주요 파일**:
    -   `app.py`: `uvicorn`으로 실행되는 FastAPI 서버의 메인 파일. `/analyze`와 같은 API 엔드포인트를 정의합니다.
    -   `bert_llm.py`: KCBERT와 Gemma 모델을 메모리에 로드하고, 입력 텍스트에 대한 실제 추론을 수행하는 핵심 로직이 포함된 파일.
    -   `best_kcbert_model.pt`, `gemma-3-1B-it-QAT-Q4_0.gguf`: AI 모델의 학습된 가중치(파라미터)를 담고 있는 파일.

### 4. 설치 및 상세 실행 방법

애플리케이션은 **Python AI 백엔드 서버**와 **Tauri 데스크톱 앱**이라는 두 개의 독립적인 프로세스로 구성되어 있으며, **반드시 순서대로 실행해야 합니다.** 개발 환경에서는 두 개의 터미널을 각각 사용해야 합니다.

#### 4.1. 사전 준비 사항
-   **Python 3.10** 및 `pip`
-   [Node.js](https://nodejs.org/) (LTS 버전 권장)
-   [Rust](https://www.rust-lang.org/tools/install) 개발 환경

#### 4.2. 의존성 설치
1.  **전체 Python 의존성 설치** (최초 1회)
    프로젝트 루트 폴더에서 `requirements.txt`를 사용하여 모든 Python 관련 라이브러리를 설치합니다.
    ```bash
    pip install -r requirements.txt
    ```

2.  **Frontend 의존성 설치**
    `demo` 폴더에서 `npm`을 사용하여 JavaScript 관련 라이브러리를 설치합니다.
    ```bash
    cd demo
    npm install
    scr_tauri
    cargo clean
    cd ..
    ```

#### 4.3. 애플리케이션 실행
1.  **(터미널 1) Python AI 서버 실행**
    `uvicorn`을 사용하여 FastAPI 백엔드 서버를 시작합니다. 이 서버는 AI 모델을 메모리에 로드하고 Tauri 앱으로부터 오는 추론 요청을 HTTP로 처리합니다. `--reload` 플래그는 코드 변경 시 서버를 자동으로 재시작하여 개발 편의성을 높여줍니다.
    ```bash
    # demo/backend 폴더로 이동
    cd demo/backend
    uvicorn app:app --reload
    ```
    서버가 `http://127.0.0.1:8000`에서 요청을 기다리는 상태가 되면 성공입니다.

2.  **(터미널 2) Tauri 애플리케이션 실행**
    `npm` 스크립트를 사용하여 Tauri 개발 서버를 시작합니다. 이 명령어는 프론트엔드 UI를 빌드하고 이를 감싸는 네이티브 데스크톱 창을 실행합니다. UI는 백그라운드에서 실행 중인 Python 서버와 통신하며 AI 분석 결과를 받아와 화면에 표시합니다.
    ```bash
    # demo 폴더로 이동
    cd demo 
    npm run tauri dev
    ```

3. **n8n 실행**
   n8n 실행을 위해 docker 혹은 npm에서 n8n을 설치한 뒤 개인 로컬 계정으로 들어가서 워크플로우를 구성 후 실행합니다. 카카오 인증을 위해서는 카카오 개발자센터에 들어가서 별도로 권한을 받아야지 실행됩니다. 카카오톡 뿐아니라 n8n에서 제공되는 텔레그램와 같이 다양한 메신저로도 확장이 가능합니다. 노코드 기반이므로 해당 프로젝트 파일에는 별도로 올리지 않습니다.
